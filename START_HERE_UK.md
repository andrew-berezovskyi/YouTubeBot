# VibeRush Discovery 1.1 — почни тут

Це оновлення вихідного коду твого бота з YouTubeBot.zip. Воно додає пошук,
завантаження, відбір, OCR/AI-перевірку водяних знаків і передачу в початкову
SQLite-чергу. Старі EXE не містять нового модуля. Новий модуль запускається через
Python командою `python run_discovery_gui.py` або `START_DISCOVERY.bat`.

## 1. Встановлення поверх свого проєкту

1. Закрий старий бот та його EXE. Зроби резервну копію `C:\YouTubeBot`.
2. Скопіюй **весь вміст цього архіву оновлення** в `C:\YouTubeBot`,
   погодившись на заміну файлів коду та об’єднання папок. Папки discovery, gui,
   queue і tests повинні лежати безпосередньо в C:\YouTubeBot.
3. Твій `config.py` не замінюється: в архіві є тільки `config.example.py`.
   Профілю браузера, баз даних, токенів і EXE в пакеті немає.
4. У терміналі VS Code відкрий `C:\YouTubeBot` і виконай:

```powershell
python -m pip install -r requirements.txt
python -m playwright install chromium
```

Ці дві команди також виконує `INSTALL_DISCOVERY.bat`. Для чистого встановлення
батник створює `config.py` з прикладу, якщо файла ще немає. Для ручного чистого
встановлення спочатку скопіюй `config.example.py` у `config.py`.

Додатково потрібні:

- FFmpeg і FFprobe: використовуються твої шляхи з `config.py`.
- Запущений Ollama та обидві моделі з `config.py`.
- **Tesseract OCR**, це окрема програма, не тільки Python-пакет pytesseract.
  Офіційна інструкція: https://tesseract-ocr.github.io/tessdoc/Installation.html
  Якщо Tesseract не в PATH, у налаштуваннях вкажи, наприклад:
  `"tesseract_cmd": "C:\\Program Files\\Tesseract-OCR\\tesseract.exe"`.
- Для частини відео YouTube yt-dlp може потребувати JavaScript runtime.
  Дотримуйся актуальних вимог: https://github.com/yt-dlp/yt-dlp#dependencies

Перевір встановлення без пошуку та без публікації:

```powershell
python check_discovery.py
```

Якщо діагностика повідомляє FAIL, виправ відповідний компонент перед обробкою.
Перевірка наявності моделі не перевіряє якість її відповідей.

## 2. Перший запуск

```powershell
python run_discovery_gui.py
```

Або запусти `START_DISCOVERY.bat`. У Python-версії основного GUI також є кнопка
`Video discovery / watermark screening`.

1. Відкрий **Налаштування**. Початкові запити: funny moments, funny fails,
   unexpected funny moments. Їх можна змінити.
2. Натисни **Знайти й перевірити**. Прапорець завантаження на YouTube спочатку
   вимкнений: цей запуск сам нічого не публікує.
3. Переглянь знайдені відео. `needs_permission` означає, що джерело ще не схвалене
   для повторного використання. Якщо маєш дозвіл на цей ролик, виділи його та
   натисни **Підтвердити дозвіл на використання**. Це не обхід водяних знаків.
4. Для власних або погоджених авторів можна один раз додати точні URL профілів
   у `approved_creator_urls`. Бот порівнює їх з uploader_url/channel_url,
   які повертає платформа. Якщо URL автора не визначається — схвалюй точний ролик.
5. Запусти наступний цикл. Схвалені відео завантажаться, пройдуть перевірки та
   отримають статус. Виділи ролик і відкрий **Кадри й звіт**.

Відсутність знака або напис Creative Commons самі по собі не дають автоматичного
допуску. Список дозволених джерел заповнюєш ти. Усі нові відео зі схваленого
автора проходять решту перевірок автоматично.

## 3. Що підтримують джерела

| Джерело | Можливість цієї версії |
|---|---|
| YouTube | Пошук за queries через yt-dlp; задані відео/плейлисти/доступні сторінки каналів |
| Reddit | Пошук за queries через публічний RSS; задані посилання на відеопости |
| TikTok | Задані відео та доступні сторінки профілів через yt-dlp; глобальний пошук TikTok за словами НЕ реалізовано |
| Vimeo | Задані посилання через yt-dlp |

`source_urls` — список посилань на конкретні відео або підтримувані сторінки.
Порожній список не заважає пошуку YouTube/Reddit. Доступність завантаження залежить
від конкретної платформи, регіону, авторизації й версії yt-dlp. RSS Reddit може
повертати 403/429; тоді джерело пропускається із записом у журналі. Пошук не
охоплює весь інтернет і не обходить CAPTCHA, платний або приватний доступ.

Якщо джерело потребує авторизації, можна вказати `cookie_file` — шлях до власного
локального Netscape cookies.txt. Це необов'язково. Cookies не експортуються ботом
з Google-профілю і не входять до архіву. Не додавай цей файл у Git.

## 4. Як перевіряються відео

- Перевірка тривалості, розміру файла, роздільності та вертикальної орієнтації.
- Повне декодування відеопотоку через FFmpeg для пошуку пошкоджень.
- SHA-256 проти історії discovery та початкової таблиці videos.
- OCR через Tesseract: handles, URL, назви деяких платформ.
- Qwen Vision через Ollama: логотипи, позначки, субтитри, відповідність темам.
- Кадри по всій тривалості та біля підозрілих моментів. Початково до 32 кадрів
  і додатково до 8 сусідніх. Для повільної частоти кадрів є резервний пошук
  останнього доступного кадру.
- Консервативне порівняння dHash кадрів із подібною тривалістю для пошуку
  можливих копій після перекодування. Можливий збіг іде на перегляд.

Це евристична перевірка, не гарантія 100%: короткі позначки між кадрами можуть
бути пропущені; OCR і AI можуть помилятися. Сильне обрізання, дзеркальні копії
та перемонтаж не гарантовано розпізнаються. Автоматичного видалення чужого
водяного знака немає. Початкова обробка лишається накладанням VibeRush і
перекодуванням; генерація монтажних рейтингів та субтитрів не додавалася.

| Статус | Значення |
|---|---|
| found | Очікує відбору |
| needs_permission | Потрібне схвалене джерело/відео |
| downloading / screening | Завантаження / перевірка |
| ready | Перевірки пройдено; доступне для основного процесу |
| watermark | Виявлено позначку; медіафайл видалено, докази збережено |
| review | Неоднозначність, збій аналізу або можлива візуальна копія; публікація заблокована |
| duplicate | Точний файл уже є в історії |
| rejected | Не підходить за параметрами/темою або відхилений вручну |
| error | Тимчасова помилка; до max_retries спроб |
| uploading | Передано в початковий процес |
| published | Початковий процес підтвердив завантаження; може бути private або public |
| upload_uncertain | Неясний результат; перевір Studio та початкову чергу перед повтором |

«Повторити перевірку» скидає помилки/відхилення для нового аналізу. Вона не
робить сумнівний ролик готовим і не повторює невизначену публікацію.

## 5. Автономний режим

Спочатку перевір кілька відео та кадри вручну. Для пробного повного циклу в GUI
увімкни **Обробляти та завантажувати**, залишивши `private`. Авторизація YouTube
використовує твій початковий BrowserProfile. Потім можна вибрати `public`.

Прапорець **Повторювати** запускає наступні цикли через заданий інтервал.
ПК, Ollama і процес повинні залишатися запущеними. Це не хмарний сервіс і не
служба автозапуску Windows. Закриття вікна зупиняє запущений ним процес.

Команди для термінала:

```powershell
# Один цикл, без YouTube upload
python run_discovery.py

# Періодичний пошук і перевірка, без upload
python run_discovery.py --watch

# Повний цикл із приватними завантаженнями
python run_discovery.py --watch --process

# Повний цикл із публічними завантаженнями
python run_discovery.py --watch --process --publish
```

Початкові ліміти: 3 завантаження з джерел за цикл; 3 спроби YouTube upload за
рухомі 24 години; мінімум 120 хвилин між спробами. Збої також витрачають ліміт,
щоб не створювати потік повторних публікацій. Цикл пошуку — кожні 60 хвилин.

Невизначені upload не повторюються самостійно. Якщо стара черга незавершена,
автономний модуль не починає нову. Спочатку узгодь результат у Studio та
віднови/заверши стару чергу через початковий GUI. Нова версія коду використовує
блокування для захисту від одночасних процесів; старий EXE про це блокування не
знає, тому не запускай його одночасно з новим модулем.

## 6. Параметри, які можна змінювати

Налаштування зберігаються у `discovery_settings.json`; відсутні поля беруться з
прикладу. `discovery_settings.example.json` — повний шаблон. JSON зберігай без
коментарів, шляхи Windows — з подвійними зворотними слешами.

| Поле | Значення |
|---|---|
| queries | Пошукові фрази та теми для AI-відбору |
| youtube_search / reddit_search | Увімкнення джерел |
| source_urls | Конкретні посилання/профілі |
| approved_creator_urls / approved_video_urls | Погоджені автори / ролики |
| results_per_query | Максимум результатів одного запиту/сторінки |
| max_candidates_per_cycle | Скільки кандидатів розглянути за цикл |
| max_downloads_per_cycle | Ліміт завантаження з джерел |
| max_download_mb / max_storage_mb | 150 МБ на ролик; бюджет Downloads + Screening 3000 МБ |
| min_duration / max_duration | Початково 5–90 секунд |
| min_height / vertical_only | Початково від 720 пікселів заввишки; тільки вертикальні |
| interval_minutes | Інтервал після завершення циклу |
| max_daily_upload_attempts | Ліміт спроб за попередні 24 години |
| min_upload_interval_minutes | Мінімальна пауза між спробами |
| max_retries / retry_minutes | Ліміт і пауза після помилки |
| sample_interval_seconds / max_frames | Частота й кількість перевірених кадрів |
| vision_timeout_seconds | Час очікування однієї AI-відповіді |
| min_topic_score | Мінімальна середня оцінка відповідності темам; це не прогноз переглядів |
| tesseract_cmd | Шлях до Tesseract, якщо не в PATH |
| cookie_file | Необов'язковий локальний файл авторизації джерел |
| download_timeout_seconds | Граничний час запиту/завантаження yt-dlp |

Бюджет диска перевіряється перед завантаженням, але не є жорсткою файловою квотою:
тимчасове об'єднання потоків і створення кадрів можуть його короткочасно перевищити.
Review-файли зберігаються до твого рішення; при заповненні бюджету завантаження
призупиняються. Історія SQLite зберігається незалежно від медіафайлів.

## 7. Де дивитися результат

- `data/discovery.db` — кандидати, результати, журнал і облік upload.
- `Downloads/<id>/` — тимчасовий файл.
- `Screening/<id>/report.json` та JPEG — час і докази перевірки.
- `Logs/discovery-worker.log` — журнал запуску з нового GUI.
- Початковий `data/youtube_bot.db` — черга аналізу, обробки та публікації.

Збережено твій початковий README у `README_LEGACY.md`. Нова документація має
пріоритет для discovery. Не публікуй runtime-папки й авторизаційні файли у Git.

## 8. Що перевірено, а що ще потрібно перевірити на ПК

Автотести: адреси й схвалення, точні та візуальні повтори, відмови OCR/AI,
обмеження, блокування, crash recovery, повний локальний шлях із змодельованими
платформами, передача в реальну початкову SQLite-чергу зі змодельованим upload.
Окремий тест створює справжній MP4, читає його через FFmpeg і розпізнає напис
Tesseract; відповідь AI в цьому тесті навмисно змодельована.

Живі пошук/завантаження на платформах, відповіді твоєї Qwen, Windows GUI,
Google-сесія і реальна публікація в цьому середовищі НЕ перевірялися.
Перевір їх на одному дозволеному відео з private перед автономним public.
Новий EXE не збирався; START_DISCOVERY запускає Python.
